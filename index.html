      Architecture, model and safeguards

      The explanation below matches the deployed static frontend and Netlify Function.

      01Audio ingestionBrowser validates supported PCM WAV.
      02Feature extractionClient calculates derived numeric acoustic signals.
      03Demonstration baselineDeterministic JavaScript classifier plus heuristics.
      04Risk Fusion0-100 risk and severity.
      05Explain and alertEvidence and an analyst workflow.
      06Verify and auditStep-up recommendation and SHA-256 chain.

      Current prototype

      • HTML5, CSS3 and modular-style vanilla JavaScript.
      • Netlify Functions JavaScript API; no Python server is required.
      • Request/response interaction, not real-time streaming.
      • Feature-level upload flow; raw WAV data is not sent by this client.
      • Function-memory state is demo-only and not durable.

      Demonstration ML Baseline

      The deterministic feature-based classifier produces a transparent risk signal from basic acoustic descriptors. It is not a Random Forest running on Netlify and is not a production-validated anti-spoofing model.

      Speaker match is a risk signal, never a biometric identity verdict. Low quality reduces confidence; it is not evidence of fraud by itself.

      Privacy and safety

      • No automatic account, payment or other irreversible actions.
      • HIGH and CRITICAL outcomes recommend step-up verification.
      • Production needs authentication, authorization, durable secure storage and defined retention rules.
      • The hash chain provides tamper evidence; it is not a blockchain network.

      Production roadmap

      • Validate with Hindi, English, Hinglish, regional accents and diverse speakers.
      • Use speaker embeddings, anti-spoofing models and rigorous held-out evaluation.
      • Add secure streaming, durable audit storage and monitored deployment.
      • Consider a permissioned ledger only if multi-party trust requires it.
