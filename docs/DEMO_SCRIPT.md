# Two-minute SIH demonstration

1. Open the deployed site. Point out that **API Online** appears only after the live `/api/health` check passes.
2. On Dashboard, explain the flow: browser-derived features -> Demonstration ML Baseline -> Risk Fusion -> explanation -> safe verification workflow -> audit chain.
3. In Simulation Lab, run **NORMAL**. It remains LOW and recommends the monitored workflow.
4. Run **CLONED VOICE**. Explain its HIGH risk evidence and the step-up verification recommendation. Do not say a voice is definitely cloned.
5. Run **REPLAY**. Contrast its replay-oriented evidence with the cloned preset.
6. Run **LOW QUALITY**. State that poor audio is an uncertainty signal, not fraud proof.
7. Run **MIXED RISK**. Show the CRITICAL result, alert creation and strongest verification recommendation.
8. Use **Request verification** on the high-risk result. The safe prototype records that a separate approved verification channel is required and does not execute a sensitive action.
9. Open Alert Center, view the alert evidence, then change an alert from NEW to INVESTIGATING. The status update reaches the API and creates a ledger event.
10. Open Analysis Monitor and Analytics to show the same live analysis state, then open Audit Ledger and click **Verify ledger**. Explain canonical event hashing, the previous-hash link, integrity verification, and why it is not a blockchain network.
11. Finish with the boundary: request/response prototype; production validation, evaluated anti-spoofing, Indian-language/accent coverage, secure streaming, authentication and durable storage are future work.

Suggested opening: “VoiceShield AI turns suspicious voice activity into explainable cybersecurity risk and asks for stronger verification before a high-risk interaction is trusted.”
